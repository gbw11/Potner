# 방향별 안전 회피 기반 자동 탐색 설계

## 목표

정적 벽이 LiDAR 정지 거리 안에 들어왔을 때 최고 우선순위의 0 속도 명령이
Nav2의 후진·회전 복구까지 차단하는 교착을 제거한다. Frontier 탐색은 계속해서
미탐색 목표를 고르고, Nav2는 경로 계획·지역 회피·후진·회전을 담당하며, 안전
계층은 위험한 방향의 속도 성분만 차단한다. 모든 주행 속도 상한은 현재 값의
70%로 낮춘다.

## 선택한 구조

`twist_mux`는 Nav2, 도킹, 수동 조작 중 하나의 요청을 `/cmd_vel_requested`로
선택한다. `safety` 노드는 이 요청과 360도 `/scan`, 좌우 ToF를 받아 방향별로
검증한 뒤 최종 `/cmd_vel`을 발행한다. `base_driver`는 검증된 최종 명령만 ESP32로
전달한다.

```text
Frontier -> Nav2 ─┐
Docking ──────────┼-> twist_mux -> /cmd_vel_requested
Teleop ───────────┘                         |
                                             v
/scan + left/right ToF ------------> directional safety -> /cmd_vel -> ESP32
```

단순히 벽을 보면 고정 각도로 회전하는 반사 행동은 사용하지 않는다. 그런 방식은
좁은 공간에서 진동하거나 같은 구역을 반복할 수 있다. 회피 방향은 최신 costmap과
목표 경로를 아는 Nav2가 선택하고, 안전 계층은 그 선택이 현재 센서 공간에서
실행 가능한지만 제한한다.

## 방향별 안전 정책

- 전방 구역이 정지 거리 안이면 양의 `linear.x`만 0으로 만든다.
- 후방 구역이 정지 거리 안이면 음의 `linear.x`만 0으로 만든다.
- 좌측 구역 또는 좌측 ToF가 막히면 양의 `angular.z`를 0으로 만든다.
- 우측 구역 또는 우측 ToF가 막히면 음의 `angular.z`를 0으로 만든다.
- 전방이 막힌 곡선 명령은 전진 성분만 제거하고 안전한 회전 성분은 유지한다.
- 두 ToF 중 하나가 근접 상태이면 전진을 금지하지만, LiDAR로 안전성이 확인된
  후진과 장애물 반대 방향 회전은 허용한다.
- `/scan`이 한 번도 없거나 제한 시간보다 오래되면 모든 명령을 0으로 만든다.
- 선택된 속도 요청이 제한 시간보다 오래되면 모든 명령을 0으로 만든다.
- NaN, infinity, 센서 범위 밖 값은 자유 공간의 증거로 사용하지 않는다. 한 구역에
  유효한 측정점이 없으면 그 방향의 이동을 허용하지 않는다.
- `/safety/blocked`는 센서에 장애물이 존재하기만 하는 상태가 아니라 요청 명령을
  실제로 제한한 상태를 뜻한다.

X4 Pro의 후방 시야가 본체에 가려져 유효한 점이 없다면 자동 후진은 허용되지
않는다. 이 경우 Nav2는 안전한 회전을 시도하고, 회전도 불가능하면 정지 상태를
유지한다.

## 자동 탐색과 복구

기존 OccupancyGrid Frontier 탐색과 목표 blacklist를 유지한다. 일반 장애물은
Nav2 DWB가 local costmap으로 우회한다. 경로 진행이 실패하면 기본 Nav2 Behavior
Tree의 costmap 정리, 저속 후진, 회전, 재계획이 실행된다. 방향별 안전 계층은
안전한 후진·회전을 통과시키므로 정적 벽 앞의 교착이 해소된다. 목표가 끝내
실패하면 기존 탐색 상태기가 해당 목표를 일정 시간 blacklist하고 다른 Frontier를
선택한다. 접근 가능한 Frontier가 확인 시간 동안 없을 때만 지도를 저장하고
탐색을 완료한다.

## 거리와 속도

전방 근접 차단은 기존 0.25m와 0.08m hysteresis를 유지한다. 전후 부채꼴은 각각
60°, 좌우 부채꼴은 대각선 사각지대를 없애기 위해 각각 120°로 두고 독립적으로
해제한다. Nav2 inflation radius는 근접
차단보다 먼저 회피 비용이 생기도록 0.30m로 조정한다.

속도 상한은 현재 값에 정확히 0.7을 곱한다.

- Nav2 선속도: 0.12 -> 0.084m/s
- Nav2 회전속도: 0.50 -> 0.35rad/s
- Nav2 선가속도/감속도: 0.25 -> 0.175m/s²
- Nav2 회전가속도/감속도: 0.80 -> 0.56rad/s²
- base wheel speed hard cap: 0.25 -> 0.175m/s
- docking approach: 0.12 -> 0.084m/s
- docking angular cap: 0.80 -> 0.56rad/s

센서 freshness나 긴급 정지 때문에 발생하는 0 속도 명령은 감속 대상이 아니다.

## 검증

ROS 비의존 정책 테스트에서 전방 전진 차단, 전방 장애물 상태의 안전한 회전,
후방 안전 시 후진 허용, 후방 장애물 시 후진 차단, 좌우 방향 회전 차단, ToF
방향성, 유효점 없는 구역의 fail-safe, scan/command timeout을 검증한다. 구성 테스트는
twist_mux 출력이 반드시 안전 노드를 거치는지, base driver가 최종 `/cmd_vel`만
구독하는지, 속도가 모두 정확히 30% 감소했는지, inflation과 recovery plugin이
유지되는지 확인한다. 마지막으로 전체 Python 테스트와 정적 구문 검사를 실행한다.
