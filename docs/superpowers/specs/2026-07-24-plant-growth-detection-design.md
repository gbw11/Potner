# 식물 성장 단계 객체 탐지 노트북 설계

## 목표

Roboflow의 `general-plant-growth-stage-model` 버전 2 데이터셋을 내려받아 데이터 누수를 점검·정제하고, Ultralytics YOLO로 `germination`, `vegetative`, `flowering` 세 클래스를 학습·평가·추론하는 한국어 JupyterLab 노트북을 제공한다.

최종 산출물은 프로젝트 루트의 `plant_growth_detection.ipynb`와 `requirements.txt`이다. 노트북 실행 결과로 `cleaned_dataset/`, `leakage_report.csv`, 통계 자료, `best.pt`를 생성한다.

## 실행 환경과 설정

노트북 상단 설정 셀에서 다음 값을 한곳에 모아 변경할 수 있게 한다.

- 원본 다운로드 경로와 정제 데이터 경로
- 학습 결과 경로와 최종 가중치 경로
- train/val/test 비율
- 고정 random seed
- 시퀀스 키 정규식 목록
- 확정 중복 pHash 임계값 5
- 검토 대상 pHash 범위 6~10
- YOLO 모델, epoch, image size, batch size, patience, workers

`ROBOFLOW_API_KEY` 환경변수만 사용하며 키를 코드나 출력에 노출하지 않는다. PyTorch의 CUDA 사용 가능 여부를 확인해 CUDA가 있으면 GPU 0, 없으면 CPU를 사용한다.

## 데이터 다운로드와 무결성 검사

Roboflow Python SDK로 YOLOv8 형식 데이터를 원본 다운로드 디렉터리에 받는다. 이 디렉터리는 이후 읽기 전용 입력처럼 다루며 파일을 수정하거나 이동하지 않는다.

데이터 YAML과 각 split의 이미지·라벨을 조사한다. 다음 항목은 정제본에서 제외하고 `leakage_report.csv`에 사유를 남긴다.

- 이미지에 대응하는 라벨 파일이 없음
- 라벨에 대응하는 이미지 파일이 없음
- 이미지가 손상되어 열리지 않음
- 라벨 행 형식, 클래스 ID, 좌표 또는 크기가 유효하지 않음
- 대상 세 클래스의 박스가 하나도 남지 않음

원본 클래스 이름을 읽어 `germination`, `vegetative`, `flowering`만 각각 0, 1, 2로 재매핑한다. `harvesting`, `no detection` 및 기타 클래스 박스는 제거한다.

## 파일명 시퀀스 분석과 그룹화

자동 그룹화 전에 실제 파일명 표본, 공통 접두·접미 토큰, 숫자 토큰 빈도를 출력한다. 노트북 Markdown과 출력에서 기본 정규식이 제거하는 패턴을 명시한다.

기본 시퀀스 키는 소문자 stem에서 다음 요소를 순서대로 제거·정규화해 만든다.

- Roboflow가 붙인 증강 해시 접미사
- `aug`, `copy`, `rot`, `rotate`, `flip`, `crop` 등 증강 표식과 인수
- `frame`, `img`, `image` 뒤의 프레임 번호
- 날짜·시각 뒤의 연속 프레임 번호
- 구분자와 말단 숫자 토큰

정규식 목록은 설정 셀에서 사용자가 실제 패턴에 맞춰 수정할 수 있다. 키가 비어 버리거나 지나치게 많은 파일이 단일 키에 포함되면 경고하고 상위 대형 그룹을 출력한다.

## pHash 보조 검증과 연결 컴포넌트

모든 유효 이미지의 pHash를 계산한다. 전체 재분할 전에 다음 규칙을 적용한다.

- 해밍 거리 5 이하는 확정 중복으로 처리해 파일명 시퀀스 그룹들을 병합한다.
- 거리 6~10은 자동 병합하거나 이동하지 않고 검토 대상으로만 보고한다.
- 거리 10 초과는 누수 판단에 사용하지 않는다.

파일명 동일 관계와 pHash 거리 5 이하 관계를 간선으로 갖는 연결 컴포넌트를 만든다. 컴포넌트가 전이적으로 커지는 현상을 확인할 수 있도록 각 이미지 행에 컴포넌트 ID와 크기를 기록하고, 컴포넌트별 최소·최대 확정 중복 pHash 거리, 시퀀스 간선 수, pHash 간선 수, 병합 근거를 기록한다. 큰 컴포넌트 순위와 크기 분포도 출력한다.

pHash 6~10 쌍은 `review_required` 판정과 거리, 양쪽 파일·시퀀스·컴포넌트를 보고서에 기록하되 컴포넌트에는 합치지 않는다.

## 그룹 단위 재분할

확정 연결 컴포넌트를 원자 단위로 사용한다. 고정 seed로 순서를 재현하고, 목표 train/val/test 비율과 세 클래스의 이미지 분포 편차를 줄이는 탐욕적 점수로 컴포넌트를 배치한다. 어떤 경우에도 개별 이미지만 이동하지 않는다.

원본은 그대로 두고 `cleaned_dataset/images/{train,val,test}`와 `cleaned_dataset/labels/{train,val,test}`에 이미지 복사본과 재매핑한 라벨을 만든다. 정제 데이터 전용 `data.yaml`을 생성한다.

test split은 학습 또는 모델 선택에 전달하지 않는다. 학습 중 검증과 `best.pt` 선택에는 val만 사용하고, 모든 설정이 확정된 뒤 test를 한 번 별도 평가한다.

## 보고서와 통계

`leakage_report.csv`는 최소한 다음 정보를 포함한다.

- 기록 종류와 판정
- 이미지 또는 라벨 경로
- 원래 split과 정제 split
- 시퀀스 키
- 컴포넌트 ID와 크기
- 비교 이미지와 pHash 거리
- 컴포넌트 최소·최대 확정 중복 거리
- 시퀀스 간선 수, pHash 간선 수, 병합 근거
- 이동 또는 제외 사유

정제 전후에 split별 이미지 수, 클래스별 박스 수, 클래스별 이미지 수, 전체 대비 split 비율을 표로 출력하고 CSV 통계 자료로도 저장한다. 샘플 이미지에 YOLO 라벨 박스를 그려 표시한다.

## 학습, 평가, 추론

Ultralytics YOLO 사전학습 가중치로 학습한다. 학습 후 다음을 수행한다.

- val 평가와 클래스별 Precision, Recall, mAP50, mAP50-95 표 출력
- val 혼동행렬 이미지 출력
- 모델 선택에 사용하지 않은 test split의 최종 클래스별 평가
- test 이미지 표본 추론과 바운딩 박스 시각화
- 학습 run의 `weights/best.pt`를 설정한 최종 경로의 `best.pt`로 복사

## 최종 검증

노트북 마지막 셀은 다음 불변 조건과 산출물을 검사하고 실패 시 예외를 발생시킨다.

- 각 시퀀스 키가 한 split에만 존재
- 각 확정 중복 컴포넌트가 한 split에만 존재
- 정제 데이터의 모든 이미지와 라벨이 일대일 대응
- `cleaned_dataset/data.yaml`과 split 디렉터리 존재
- `leakage_report.csv` 존재
- 정제 전후 통계 CSV 존재
- `best.pt` 존재

## 오류 처리와 검증 전략

API 키 누락, 잘못된 비율 합계, 필요한 클래스 부재, 빈 split, 파일 손상, 잘못된 라벨, 학습 가중치 부재에는 원인을 설명하는 한국어 예외를 제공한다. 노트북 파일 자체는 JSON 파싱, 셀 순서, 코드 셀 문법 컴파일, 필수 문자열 및 산출물 경로 포함 여부를 정적 검증한다. 실제 데이터 다운로드와 GPU 학습은 API 키·네트워크·연산 자원이 필요한 사용자 실행 단계로 남긴다.
